## T-06 — BUILT and CLOSED (`6e5da887` code · `2879a92` docs)

**What changed.** The record that says an act was undone now extends the hash chain, exactly like every
other journal row, and the chain event says it is a reversal.

**The defect, measured before it was touched.** `log()` writes the journal row and then the chain, so
every ordinary write is covered. `markUndone` built the trace row with `createLogEntity` on a forked
EntityManager and never called `appendToLedger`. And redo was **already covered**, because it
re-executes through `commandBus.execute`. So the same reversal was chained forward and unchained
backward, which is what made it a defect rather than a choice.

**Three changes.** `markUndone` appends; the event carries `historyAction: 'undo'` and `sourceLogId`
(an undo whose event type was the original command id was indistinguishable from the act it reverses);
and the fork is gone, with `commandBus.undo` inside `runInTransaction` so the trace, its event and the
business reversal commit together. `verifyUndoCoverage` compares the journal against the chain in both
directions, as a **separate answer** from the hash walk, because a missing event is not a broken link.
